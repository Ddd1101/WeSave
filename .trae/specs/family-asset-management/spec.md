# 家庭资产管理系统 - 产品需求文档

## Overview
- **Summary**: 一个基于 Web 的家庭资产（银行账户、股票、基金、黄金、外部借款等）管理系统，支持按条目对资产进行增删改查，以表格形式展示资产类别/名称/当前价值/购买日期/购买价格/备注，并自动计算资产总计与占比，所有数据持久化存储。
- **Purpose**: 替代 Excel 表格记账，提供更直观、可交互的资产总览，便于家庭成员长期追踪家庭财富变化。
- **Target Users**: 家庭成员（单人或多人共用），无专业财务背景。

## Goals
- 以"资产条目"为最小管理单元，提供完整的 CRUD（新增/查看/编辑/删除）能力。
- 以表格 + 汇总的形式展示资产，支持按类别分组并自动计算总计与占比。
- 数据持久化到本地文件数据库（SQLite），刷新/重启浏览器与服务器后数据不丢失。
- 提供简洁直观的界面，操作 3 步内可完成一次资产条目的新增或修改。

## Non-Goals (Out of Scope)
- 不做多用户账号/权限体系（一期为单家庭/单用户使用）。
- 不做实时行情接入（股票/基金价格由用户手工录入或后期扩展）。
- 不做复杂的投资分析、K 线、回测等。
- 不做移动端原生 App，仅提供 Web 端（可响应式适配手机浏览器）。

## Background & Context
- 当前用户以 Excel 表格记录家庭资产，列包含：资产类别、资产名称、当前价值（按日期）、购买日期、购买价格、备注，并计算总计与占比。
- 现有目录结构：`Page/`（前端源码）、`Server/`（后端源码），计划以 Vue3 前端 + Node.js/Express 后端 + SQLite 数据库构建。
- 资产类别示例（来自参考表格）：存款、投资资产、其他资产（含外部借款，负数表示负债）。

## Functional Requirements
- **FR-1 资产条目管理**：系统支持对资产条目进行列表展示、新增、编辑、删除。
- **FR-2 字段定义**：每条资产条目包含字段：ID、资产类别、资产名称、当前价值（数值）、购买日期（可选）、购买价格（可选）、备注（可选）、创建/更新时间。
- **FR-3 分类汇总**：按资产类别分组展示，显示每个类别小计，并在表格底部显示总资产金额；负数值（如外部借款）以红色或负号显示。
- **FR-4 占比计算**：每条资产显示"资产总计/占总金额比例（%）"，占比 = 该条目当前价值 ÷ 所有条目当前价值（取绝对值之和，或取总和，具体见 AC）× 100%。
- **FR-5 搜索与筛选**：支持按资产名称关键字搜索，支持按资产类别筛选。
- **FR-6 持久化**：数据通过后端持久化到 SQLite 数据库，重启后端与浏览器后数据保留。
- **FR-7 REST API**：后端提供 `GET /api/assets`、`POST /api/assets`、`PUT /api/assets/:id`、`DELETE /api/assets/:id` 等接口。

## Non-Functional Requirements
- **NFR-1 性能**：单次列表查询响应时间 < 200ms（数据量 ≤ 1000 条）。
- **NFR-2 可用性**：新增/编辑表单在前端做基础校验（名称非空、数值为数字）。
- **NFR-3 可访问性**：使用 Element Plus 等组件库提供键盘可操作界面与中文展示。
- **NFR-4 代码组织**：前端按 pages / components / api / utils 分层，后端按 routes / db / middleware 分层。

## Constraints
- **Technical**: 前端 Vue3 + Element Plus；后端 Node.js (Express)；数据库 SQLite（`better-sqlite3` 或 `sqlite3`）。
- **Business**: 仅中文界面，一期无登录认证。
- **Dependencies**: Node.js ≥ 16；npm。

## Assumptions
- 部署环境为 Windows 本地开发机，通过 `npm run dev` 同时启动前后端。
- 数据库文件存放于 `Server/data/assets.db`。
- 资产"占比"分母为所有条目当前价值之和（不含负条目取绝对值的特殊处理，若出现负数占比需在前端以负数或红色标识）。

## Acceptance Criteria

### AC-1: 资产列表展示
- **Given**: 数据库中已存在若干资产条目
- **When**: 用户打开首页
- **Then**: 页面以表格形式展示所有条目，表头包含"资产类别/资产名称/当前价值/购买日期/购买价格/备注/占比"，底部显示总资产金额
- **Verification**: `programmatic` + `human-judgment`

### AC-2: 新增资产条目
- **Given**: 用户在首页点击"新增"按钮
- **When**: 填写必填字段（资产类别、资产名称、当前价值）并提交
- **Then**: 表格立即出现新条目，新条目出现在数据库中，刷新后仍存在
- **Verification**: `programmatic`

### AC-3: 编辑资产条目
- **Given**: 某条资产条目已存在
- **When**: 用户点击该条目的"编辑"按钮，修改字段并提交
- **Then**: 该条目字段被更新，updatedAt 被刷新，前端列表立即更新
- **Verification**: `programmatic`

### AC-4: 删除资产条目
- **Given**: 某条资产条目已存在
- **When**: 用户点击"删除"并确认
- **Then**: 该条目从列表与数据库中移除；删除不可恢复
- **Verification**: `programmatic`

### AC-5: 分类汇总与占比计算
- **Given**: 数据库中有多个类别资产（含负值/借款）
- **When**: 列表渲染时
- **Then**: 每类别小计正确累加；底部总计 = 所有条目当前价值之和；每条"占比" = 条目价值 ÷ 总计绝对值（或总和，依后期定）× 100%，保留 2 位小数
- **Verification**: `programmatic`

### AC-6: 持久化验证
- **Given**: 系统中已录入若干条目
- **When**: 重启后端服务，再重新打开页面
- **Then**: 所有数据仍然存在
- **Verification**: `programmatic`

### AC-7: 搜索与筛选
- **Given**: 列表中存在多条数据
- **When**: 用户在搜索框输入关键字或选择类别筛选
- **Then**: 列表实时过滤出匹配项，总计与占比基于过滤后数据重新计算（或仍基于全部数据，二选一，需在实现中统一）
- **Verification**: `human-judgment`

## Open Questions

- [ ] 是否需要多币种支持？目前假设仅人民币。
- [ ] 是否需要导入/导出 CSV，以便从现有 Excel 迁移数据？（推荐：一期支持导出 CSV，导入留作二期）
